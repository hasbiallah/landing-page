# PRD v1.1 — Migrasi Astro + Share Preview + Favicon

> **Source of truth**: https://github.com/hasbiallah/landing-page/issues/6
> **Status**: ready-for-agent
> **Supersedes**: ADR-0001 (single HTML file, no framework)
> **PRD sebelumnya**: v1 (issue #1, shipped) — lihat `/PRD.md`

## Problem Statement

PRD v1 (issue #1) sudah live di https://landing-page-fawn-theta.vercel.app dengan stack 1 file HTML + Tailwind CDN. Setelah live, ditemukan tiga hal yang menghambat konversi atau profesionalitas brand:

1. **Performance**: Tailwind via CDN = ~350KB blocking JS di first load, FCP/LCP di HP kentang melambat. PRD §5 target <2.5s belum terukur (GA4 belum aktif, ADR-0002).
2. **Trust signal — share preview**: Saat link di-share ke WA (kanal utama konversi, ADR-0003), preview kosong karena tidak ada OG image. CTR share turun, penerima pesan tidak tertarik buka.
3. **Trust signal — favicon**: Halaman tidak punya favicon. Tab browser blank, brand tidak dikenali, terasa kurang profesional.

Konten copy live (Hero, Pain→Solusi, Paket, Cara Kerja, FAQ, Sticky CTA) sudah match PRD §4 dan final — tidak akan diubah. Section Portofolio/Social Proof (PRD §4.4) tetap kosong sampai aset klien early bird tersedia (ADR-0004).

## Solution

Migrasi stack dari HTML+CDN ke **Astro static site** dengan Tailwind via Vite (precompiled, ~10KB). Output tetap HTML statis, deploy ke Vercel sebagai static hosting. Di saat yang sama, lengkapi `<head>` dengan OG/Twitter tags + favicon (placeholder geometris) dan GA4 wiring siap pakai (Measurement ID placeholder, owner isi manual).

**Batasan scope**: copy identik, struktur section identik, warna/font/nomor WA identik. Yang berubah hanya: build pipeline, `<head>` tags, dan event tracking GA4. **Tidak ada** section baru, tidak ada komponen tambahan.

## User Stories

### Konversi & performance

1. Sebagai pengunjung mobile, saya ingin halaman load cepat di 4G (target Lighthouse Performance >90, LCP <2.5s sesuai PRD §5), agar saya tidak back sebelum konten muncul.
2. Sebagai pemilik hasbi.dev, saya ingin Lighthouse Mobile audit bisa diulang kapan saja via `npm run audit`, agar saya bisa track regresi performance antar-iterasi.

### Share preview & brand

3. Sebagai pengirim link, saya ingin preview di WA/Telegram/iMessage menampilkan gambar, judul, dan deskripsi yang menarik, agar penerima tertarik untuk buka.
4. Sebagai pengunjung, saya ingin melihat icon hasbi.dev di tab browser, agar brand lebih mudah dikenali saat saya buka banyak tab.

### Konfigurasi & maintainability

5. Sebagai pemilik hasbi.dev, saya ingin membuka satu file `src/config.ts` untuk mengubah nomor WA, pesan default, dan GA4 ID, agar konfigurasi terpusat.
6. Sebagai pemilik hasbi.dev, saya ingin semua tombol WA otomatis mengirim event `wa_click` ke GA4 dengan label lokasi tombol (hero, paket-hemat, sticky, dll), agar saya tahu tombol mana yang paling banyak diklik.
7. Sebagai developer接手 repo ini, saya ingin `astro build` lokal bisa di-run dengan satu perintah dan menghasilkan `dist/index.html` yang isinya secara visual identik dengan `index.html` lama, agar saya bisa verify tidak ada regresi konten.

### Deployment & rollback

8. Sebagai pemilik hasbi.dev, saya ingin push ke git → Vercel auto-deploy dengan build command `astro build`, agar workflow tidak berubah.
9. Sebagai pemilik hasbi.dev, saya ingin `index.html` lama tetap di git history (tidak dihapus), agar rollback cukup revert commit.
10. Sebagai pemilik hasbi.dev, saya ingin `vercel.json` punya satu entry point yang jelas, agar tidak ada ambiguity saat deploy.

### Dokumentasi

11. Sebagai owner, saya ingin satu ADR baru yang mendokumentasikan keputusan migrasi dan secara eksplisit supersede ADR-0001, agar tidak ada konflik doktrin antar-ADR.
12. Sebagai owner, saya ingin `CONTEXT.md` diperbarui dengan term "Tech Stack" yang menunjuk ke Astro, agar vocabulary repo konsisten.

## Implementation Decisions

- **Framework**: Astro v4+ dengan `output: 'static'`. Alasan: zero JS by default, Tailwind via Vite precompiled (bukan CDN), MDX built-in untuk iterasi blog nanti, deploy ke Vercel static hosting tanpa adapter khusus.
- **No Vercel adapter**: Astro static output adalah HTML statis biasa — Vercel static hosting serve langsung dari `dist/`. `@astrojs/vercel` **tidak diperlukan** (itu untuk SSR/serverless). Confirmed via dokumentasi Astro.
- **Supersedes ADR-0001**: ADR-0001 (single HTML file, no framework) diganti. Goal "1 halaman statis" tetap. Goal "no framework" diganti "static-first framework dengan output HTML statis". ADR baru `0005-migrate-to-astro.md` menjelaskan trade-off dan trigger untuk re-evaluate (blog, dashboard, halaman dinamis).
- **Tailwind**: `@astrojs/tailwind` integration. Config di `tailwind.config.mjs`, extend warna `wa` & `wa-dark` dipertahankan.
- **Struktur file minimum** (sesuai YAGNI, refactor nanti saat kompleksitas muncul):
  ```
  src/
    config.ts           # WA_NUMBER, WA_MESSAGE, GA4_ID (placeholder)
    lib/
      wa.ts             # buildWaUrl(location), attachWaTracking()
    pages/
      index.astro       # semua section inline, copy 1:1 dari index.html lama
  public/
    favicon.png         # placeholder 512x512 (lingkaran hijau + 'h')
    og-image.png        # placeholder 1200x630
  ```
  **Tidak ada** `src/layouts/`, **tidak ada** `src/components/` untuk v1.1 — semua section inline di `index.astro`. Folder-folder itu ditambahkan saat benar-benar dibutuhkan (≥2 pages atau ≥3 komponen复用).
- **Konfigurasi terpusat**: `src/config.ts` jadi single source of truth. Tidak ada hardcode string `wa.me/62...` di komponen.
- **OG image & favicon**: Placeholder geometris (lingkaran hijau WA + teks "h") pakai tool sederhana (bisa Inkscape/CLI atau 1 file HTML→canvas→export). Owner replace manual kapan saja. Ukuran: `favicon.png` 512×512 (modern), `og-image.png` 1200×630.
- **GA4 wiring**: `<script>` di `index.astro` load `https://www.googletagmanager.com/gtag/js?id={GA4_ID}` async, plus listener global untuk `click` pada `[data-wa-location]` → emit `wa_click` event. Measurement ID placeholder `G-XXXXXXXXXX` sampai owner isi.
- **Vercel config**: `vercel.json` di-update: `buildCommand: "astro build"`, `outputDirectory: "dist"`. Hapus `routes` array (Astro static tidak butuh SPA fallback).
- **Keamanan**: Static output = no new attack surface. **CSP di-defer** ke iterasi security terpisah — kombinasi inline `<script>` (GA4 + Tailwind config) + eksternal (Google Fonts, GA4 endpoint) butuh nonce/hash strategy yang tidak trivial. Untuk v1.1: HTTPS Vercel default cukup.
- **Dependensi minimum**: `astro`, `@astrojs/tailwind`, `tailwindcss`. Tidak ada runtime deps lain, tidak ada Playwright/test framework.
- **Dependensi dev minimum**: opsional `@lhci/cli` untuk Lighthouse CI script. Bisa di-skip dulu, owner audit manual via DevTools.
- **Tidak mengubah**: Konten copy, urutan section, warna brand, font, sticky CTA behavior, nomor WA `6281286057569`, pesan default.

## Testing Decisions

- **Apa yang dites**: (1) copy identik dengan live, (2) Lighthouse Performance >90 mobile, (3) OG/favicon muncul saat di-share.
- **Seam tunggal**: `dist/index.html` vs `index.html` lama. Diff innerText (skip script/style/atribut) harus kosong.
- **Verifikasi otomatis minimum** — **tanpa Playwright** (overkill):
  - 1 file `scripts/verify-copy.mjs` pakai Node built-in (`fs`, `path`) + `node:html`/regex untuk strip tag, diff innerText. ~30 baris, zero dependency tambahan.
  - Run via `npm run verify` setelah `astro build`.
- **Verifikasi manual** (sebelum push ke main):
  - `npm run build && npx serve dist` → buka di browser, viewport 375px
  - Klik semua tombol WA → pastikan membuka WA dengan nomor `6281286057569` dan pesan default
  - Lighthouse DevTools mobile audit → Performance >90, LCP <2.5s
  - Paste URL ke WA web → preview menampilkan OG image + judul + deskripsi
  - Tab browser menampilkan favicon
- **Tidak ada unit test** untuk komponen — overkill untuk 1 halaman inline.
- **Tidak ada Playwright/E2E** — scope v1.1 terlalu kecil untuk justify dependency tersebut.

## Out of Scope

- Section Portofolio/Social Proof (PRD §4.4) — butuh aset asli dari klien early bird, iterasi terpisah
- Meta Pixel — ADR-0002 masih berlaku (GA4 only)
- Custom domain `hasbi.dev` — terpisah
- CSP/security headers — iterasi security terpisah
- Animasi, intersection observer, atau JavaScript interactivity di luar GA4 tracking
- Migrasi ke React/Preact/Next.js — Astro cukup
- Refactor ke `src/components/` / `src/layouts/` — YAGNI, semua inline di `index.astro` untuk v1.1
- Lighthouse CI di Vercel — owner audit manual via DevTools untuk v1.1
- Otomasi replace placeholder favicon/OG-image — manual owner

## Further Notes

- **Konflik dengan ADR-0001**: PRD ini secara eksplisit men-supersede ADR-0001. ADR baru `0005-migrate-to-astro.md` akan dibuat saat eksekusi, dengan referensi silang ke ADR-0001.
- **Konflik minor dengan ADR-0002**: GA4 wiring jadi sedikit lebih dalam (di Astro `<script>`), tapi ID placeholder & event names sama. Tidak perlu supersede.
- **Konten tidak berubah**: Owner eksplisit mengkonfirmasi Q2 dan Q7 grill session bahwa copy live (kecuali social proof angka `47+` yang memang tidak ada di live) sudah final. Migrasi = copy 1:1, no rewrite.
- **Risk**: Kalau `astro build` gagal di Vercel (env/dep issue), rollback = `git revert` commit terakhir. `index.html` lama tetap di git history dengan path lama, `vercel.json` akan di-restore ke versi sebelumnya. **Tidak rename** `index.html` → `index.html.bak` (itu akan bikin Vercel kehilangan entry point). Cukup revert commit.
- **Performance target adjustment**: PRD §5 target <2.5s untuk LCP. US #1 menyebut "loading cepat" tanpa angka baru. Kita tidak meningkatkan target performance, hanya memenuhi target yang sudah ada dengan stack yang lebih efisien.
